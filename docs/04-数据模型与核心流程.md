# 04 · 数据模型与核心流程

> 版本：v1.0 ｜ 金额、状态码、表前缀以 [00](00-术语与口径.md) 为准。
> 本文是 DDL 设计依据，不替代最终 Flyway 脚本。

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 引擎/字符集 | InnoDB，`utf8mb4_general_ci` |
| 主键 | `id BIGINT UNSIGNED AUTO_INCREMENT` |
| 业务单号 | `VARCHAR(32)` + 唯一索引 |
| 金额 | `BIGINT`，单位分 |
| 比例 | `INT`，单位 bp（10000 = 100%） |
| 时间 | `DATETIME(3)`，UTC+8；统一 `created_at`/`updated_at` |
| 软删除 | `deleted TINYINT DEFAULT 0`（仅低频主数据） |
| 乐观锁 | `version INT DEFAULT 0` |
| 审计 | `created_by`/`updated_by`（后台表） |
| 枚举 | 整数 code，字典表维护 |
| 快照 | 订单保存价格、地址、分账规则 JSON 快照 |
| 分区 | 订单、流水、轨迹按月分区；保留 3 年在线 |
| 禁止 | 外键约束（应用层保证）、`DECIMAL` 存金额、跨模块查表 |

```sql
CREATE TABLE p_stock (
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  sku_id BIGINT UNSIGNED NOT NULL,
  stock INT NOT NULL DEFAULT 0,
  locked_stock INT NOT NULL DEFAULT 0,
  sold_count INT NOT NULL DEFAULT 0,

```

扣减 SQL：

```sql
UPDATE p_stock
SET locked_stock = locked_stock + #{qty}, version = version + 1
WHERE sku_id = #{skuId} AND stock - locked_stock >= #{qty};
```

## 4. 状态机

统一使用 [00](00-术语与口径.md) 第 3–5 节的状态字典。**禁止在本文件之外定义新状态。**

订单主链路：

```
10 待支付 → 20 待接单 → 30 制作中 → 35 待取餐 → 40 配送中 → 45 已送达 → 50 已完成
                │            │            │            │            │
                └────────────┴────────────┴────────────┴────────────┴──► 60 售后中
10 → 91 已关闭（15 分钟未支付）
任意前置状态 → 90 已取消（按取消规则）
```

配送链路：

```
10 待派单 → 15 抢单池 → 20 骑手已接单 → 25 已到店 → 30 已取餐 → 40 配送中 → 50 已送达
                                                              └→ 70 异常
任意 → 60 已取消
```

## 5. 关键时序

### 5.1 下单支付

```
用户 → 订单服务: 提交订单(submitToken)
订单服务 → 库存服务: 条件更新锁定库存
库存服务 --> 订单服务: 成功/失败
订单服务 → DB: 创建订单(status=10) + 明细 + 状态流水 + outbox
订单服务 --> 用户: orderNo + 支付参数
用户 → 微信支付: 支付
微信 --> 支付服务: 回调(验签)
支付服务 → DB: 幂等 CAS + 支付单 PAID + outbox(pay.succeeded)
支付服务 --> 订单服务: 事件消费 → status=20
订单服务 → 库存服务: locked→sold
订单服务 → 商家端: 新单推送
```

### 5.2 接单配送

```
商家 → 订单服务: 接单(status=30)
订单服务 → 配送服务: 创建配送单(status=10)
配送服务 → 骑手: 派单/抢单
骑手 → 配送服务: 接单(20) → 到店(25) → 取餐(30)
配送服务 → 订单服务: 订单 status=40
骑手 → 配送服务: 送达(50) + 拍照
配送服务 → 订单服务: 订单 status=45，进入售后期
售后期结束 → 定时任务: 订单 status=50 + 触发分账
```

### 5.3 退款（分账前/后）

```
用户 → 售后: 申请退款
售后 → 订单: 校验状态与可退金额
分账前:
  售后 → 支付服务: 微信退款
  支付服务 → DB: 退款单 SUCCESS + outbox
分账后:
  售后 → 资金服务: 分账回退
  资金服务 → 微信: 分账回退
  成功 → 退款单 SUCCESS
  失败 → PART_REVERSED + 欠款台账 + 平台垫付
用户 → 收到退款（始终全额）
```

### 5.4 分账与结算

```
售后期结束 → 定时任务(02:00):
  查当日待分账订单
  → 校验 分账总额 ≤ 实付 且 ≤ 30%
  → 生成 fund_split_order + detail
  → 调用微信分账
  → 成功: SUCCESS；失败: 重试3次 → 人工
  → 生成结算凭证（T+1 微信自动结算）
  → 生成商户台账流水
  → 次日对账
```

## 6. 校园特殊模型

### 6.1 地址层级

```
c_campus（校区）
  └─ c_zone（园区）
       └─ c_building（楼栋）
            ├─ 楼层/房间（用户地址文本）
            └─ c_delivery_point（集配点）── c_locker（格口）
```

### 6.2 配送定价优先级

1. `building_id` 精确匹配（最高）；
2. `zone_id` 匹配；
3. `campus_id` 默认规则；
4. 同优先级按 `priority` 降序，再按 `effective_from` 最新。

计价结果写入订单快照，事后调价不影响历史订单。

### 6.3 预约产能

- `p_capacity_slot` 按门店 + 日期 + 5 分钟时段配置 `capacity`；
- 下单时 `used + qty <= capacity` 条件更新，否则不可选；
- 取消/退款释放 `used`；
- 商家可临时关闭时段。

### 6.4 校历

`c_calendar` 标记 `SEMESTER` / `HOLIDAY` / `EXAM` / `EVENT`；定时任务按日期切换假期模式。

## 7. 一致性与幂等

| 场景 | 方案 |
|---|---|
| 下单 | submitToken + 唯一索引 + 状态 CAS |
| 库存 | DB 条件更新；Redis 仅缓存 |
| 支付回调 | 唯一索引 `(channel, wx_transaction_id)` + 幂等表 + 状态 CAS |
| 退款 | `refund_no` 唯一 + 状态 CAS |
| 分账 | `split_no` 唯一 + 状态门禁 + 退款互斥锁 |
| 跨域事件 | Outbox + 消费幂等（event_id 唯一） |
| 定时任务 | ShedLock 防多实例重复 |
| 对账 | 日终 T+1；差异工单；月末全量重算 |
| 悬挂单 | 每日扫描：已支付未接单、已送达未完成、已退款未回退 |

## 8. DDL 检查清单

- [ ] 所有金额字段为 `BIGINT`，注释单位「分」；
- [ ] 所有状态字段有字典与注释；
- [ ] 业务单号有唯一索引；
- [ ] 高频查询有组合索引（user_id+status+created_at 等）；
- [ ] 订单/流水/轨迹按月分区；
- [ ] 无外键约束；
- [ ] 无 `SELECT *` 的 Mapper；
- [ ] 软删除仅用于主数据，订单/资金不删除；
- [ ] 资金流水只增不改，冲正用反向流水；
- [ ] 每张表有 `created_at`/`updated_at`；
- [ ] 敏感字段加密（手机号/身份证/银行卡）；
- [ ] Flyway 脚本命名 `V{版本}__{描述}.sql`，禁止修改已执行脚本。
