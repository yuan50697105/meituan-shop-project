# 09 · 测试与上线

> 版本：v1.0 ｜ 验收指标见 [07](07-路线图与验收.md)。

---

## 1. 测试策略总览

```
        ┌─────────────┐
        │  E2E / UAT  │  5%   关键链路、真机、小程序
        ├─────────────┤
        │  契约/接口   │ 15%   OpenAPI、前后端契约
        ├─────────────┤
        │  集成测试    │ 30%   DB/Redis/微信沙箱/Testcontainers
        ├─────────────┤
        │  单元测试    │ 50%   金额、状态机、分账、优惠分摊
        └─────────────┘
```

**硬性要求：**

- 资金相关（金额、分账、退款、优惠分摊）单元测试覆盖率 **≥90%**；
- 订单状态机、库存扣减、幂等逻辑必须有单测；
- 每个 P0 接口至少 1 个集成测试；
- CI 阻断：单测失败、ArchUnit 违规、OpenAPI 不兼容。

---

## 2. 测试环境

| 环境 | 用途 | 数据 | 访问 |
|---|---|---|---|
| `dev` | 开发自测 | 造数脚本 | 内网 |
| `test` | 集成/接口/自动化 | 脱敏测试数据 | 内网 |
| `staging` | UAT/压测/灰度 | 生产同构小数据 | VPN |
| `prod` | 生产 | 真实 | 严格权限 |

**原则：**

- 环境隔离，禁止测试数据进生产；
- 微信支付使用沙箱；生产验证用 1 分钱真实订单；
- 造数工具支持：用户/商家/商品/订单/骑手/优惠券；
- 测试数据脱敏，禁止使用真实学生信息。

## 3. 测试类型

### 3.1 单元测试（JUnit 5 + Mockito）

重点：

- 金额计算：优惠分摊、尾差、退款、分账；
- 状态机：合法/非法迁移；
- 库存：并发扣减、锁定/释放/对账；
- 幂等：重复提交、重复回调；
- 分账规则：佣金、封顶、保底、优先级；
- 配送定价：楼栋/楼层/时段优先级。

### 3.2 集成测试（Testcontainers）

- MySQL + Redis 真实容器；
- 支付回调：验签、重复、乱序；
- 分账：成功/失败/部分成功/回退；
- 对账：账单解析、差异生成；
- Outbox：投递、重试、死信。

### 3.3 接口/契约测试

- Springdoc OpenAPI 生成；
- 前端 `openapi-typescript` 类型校验；
- 契约变更 CI 检查（破坏性变更阻断）；
- 错误码、分页、鉴权、数据权限全覆盖。

### 3.4 E2E 测试

| 端 | 工具 | 场景 |
|---|---|---|
| 学生小程序 | 微信开发者工具自动化 / miniprogram-automator | 登录→选店→下单→支付→查看订单→退款 |
| 商家小程序 | 同上 | 接单→出餐→拒单→退款审核 |
| 骑手 App | Appium / uni-app 自动化 | 上线→接单→取餐→送达→收入 |
| 管理后台 | Playwright | 审核→退款复核→对账→报表 |

### 3.5 兼容性测试

- 微信小程序：iOS/Android 主流机型（iPhone 12+、华为/小米/OPPO/vivo 各 2 款）；
- 微信版本：近 3 个稳定版本；
- 屏幕：小屏/大屏/刘海/折叠屏；
- 网络：4G/5G/Wi-Fi/弱网（2G 模拟）；
- 骑手 App：Android 8–15，厂商后台保活策略。

## 4. 性能测试

### 4.1 目标

| 场景 | 目标 |
|---|---|
| 峰值下单 | 8000 单/日，午峰 1 小时 3000 单，TPS ≥ 10 |
| 订单查询 | QPS 300，P99 < 300ms |
| 商品/店铺列表 | QPS 500，P99 < 200ms |
| 支付回调 | QPS 50，P99 < 500ms |
| 骑手定位 | 120 骑手 × 10s，写入 QPS 12，Redis 延迟 < 10ms |
| 批量分账 | 8000 单在 2 小时内完成，成功率 ≥99.9% |

### 4.2 场景

1. 午峰混合流量：浏览 70% + 下单 20% + 支付 10%；
2. 秒杀/大促：单 SKU 1000 QPS（如做）；
3. 批量分账：02:00 并发 100，观察微信限流；
4. 弱网/断网：骑手离线恢复；
5. 故障注入：Redis 宕机、MySQL 主从延迟、微信超时。

### 4.3 工具

- JMeter / k6（HTTP）；
- Gatling（复杂场景）；
- Redis benchmark；
- 慢 SQL 分析（`EXPLAIN` + 慢查询日志）；
- 前端：Lighthouse（H5）、小程序性能面板。

## 5. 安全测试

| 项 | 方法 |
|---|---|
| 渗透测试 | OWASP ZAP / Burp Suite + 第三方 |
| 越权 | 水平/垂直越权用例（改 ID、改角色、跨校区） |
| 注入 | SQL/NoSQL/命令注入 |
| XSS/CSRF | 后台与用户输入 |
| 支付安全 | 回调伪造、金额篡改、重复回调、分账参数篡改 |
| 文件上传 | 类型绕过、图片马、路径穿越 |
| 敏感数据 | 日志/响应/缓存泄露 |
| 限流/防刷 | 验证码、设备指纹、频控 |
| 依赖漏洞 | OWASP Dependency-Check / Trivy |
| 等保 | 二级/三级测评项自查 |

**准出：** 无高危、无中危未修复；低危有整改计划。

## 6. 缺陷分级

| 级别 | 定义 | 修复时限 |
|---|---|---|
| P0 阻断 | 无法下单/支付/配送/分账，资金错误 | 2 小时 |
| P1 严重 | 主流程可用但结果错误、数据不一致 | 24 小时 |
| P2 一般 | 部分功能异常、体验问题 | 3 天 |
| P3 轻微 | 文案/样式/建议 | 下个版本 |

**上线准出：** P0/P1 清零；P2 ≤5 且有计划；P3 记录。

## 7. UAT 验收

| 角色 | 场景 | 通过标准 |
|---|---|---|
| 学生 | 下单→支付→催单→退款→评价 | 全流程无阻断 |
| 商家 | 接单→出餐→拒单→对账 | 订单/金额正确 |
| 骑手 | 上线→接单→取餐→送达→收入 | 状态/收入正确 |
| 财务 | 分账→结算→对账→差异处理 | 零差异 |
| 运营 | 审核→配置→活动→客服 | 权限/审计正确 |
| 校方 | 数据看板、食安、投诉 | 满足监管要求 |

**UAT 周期：** 2 周；每日缺陷例会；准出签字。

## 8. 发布流程

```
代码提交 → CI（编译/单测/ArchUnit/依赖扫描）
  → 构建镜像 → 部署 test → 自动化回归
  → 部署 staging → 压测/安全/UAT
  → 人工审批（产品/技术/运营）
  → 生产灰度（1 栋楼）→ 观察 24h
  → 扩大灰度 → 全量
```

**发布窗口：** 周一/周二 10:00–11:00 或 14:00–16:00；避开饭点与周五。

**发布检查：**

- [ ] 数据库变更已 Review，可回滚；
- [ ] 配置/开关已准备；
- [ ] 监控告警已配置；
- [ ] 回滚脚本/镜像就绪；
- [ ] 值班人与联系方式确认；
- [ ] 公告/客服话术准备。

---

## 9. 回滚

| 场景 | 动作 |
|---|---|
| 应用故障 | 切回上一版本镜像（保留 3 个版本） |
| 数据库变更 | 优先向前兼容；必要时执行回滚脚本（提前演练） |
| 支付/分账异常 | 关闭相关功能开关，保留查询 |
| 小程序审核失败 | 回退上一线上版本，H5 兜底 |
| 数据错误 | 停止写入，备份，修复脚本，复核 |

**回滚判据：** 支付成功率 <95%、下单成功率 <90%、P0 缺陷、分账失败 >10 单/日、重大食安/舆情。
