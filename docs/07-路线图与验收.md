# 07 · 路线图与验收

> 版本：v1.0 ｜ 规模与状态口径见 [00](00-术语与口径.md)。
> 排期按「合规前置、单点打透、分期交付」设计，总周期 15 个月。资质办理是最大不确定性，M0 延期会顺延后续。

---

## 1. 关键路径

```
运营主体设立/授权 ─┐
支付服务商资质/进件 ─┼─► 商户进件 ─► 支付分账联调 ─► 试点营业
校园准入/集配点场地 ─┤
等保/APP备案 ───────┘

产品原型 ─► 技术验证（骑手App保活/定位）─► P0开发 ─► 试点 ─► P1 ─► P2
```

**前置条件（未完成不进入 M1）：**

- [ ] 运营主体确定并能签约、收款、开票；
- [ ] 微信支付服务商资质与至少 1 家商户进件完成；
- [ ] 校方书面同意试点区域、集配点场地、骑手准入；
- [ ] 平台服务费定价与合规意见；
- [ ] 等保定级备案启动、小程序主体与类目确认。

## 3. 里程碑

### M0 · 立项与合规前置（第 1–3 月）

| 交付 | 验收标准（DoD） |
|---|---|
| 项目立项书、预算、组织 | 校方批复 |
| 运营主体与授权 | 能签署商户协议、开票 |
| 支付服务商资质/进件 | 至少 1 家商户进件成功，分账权限已签约 |
| 商户与用户调研 | ≥30 家商户访谈、≥300 份学生问卷 |
| 高保真原型（四端） | 评审通过 |
| 技术验证 | 骑手 App 后台定位/推送 Demo 通过；分账沙箱联调通过 |
| 集配点场地意向 | ≥3 个点位意向书 |
| 合规清单启动 | 等保、APP 备案、食安、合同模板 |

**Gate：** 上述 8 项全部完成才进入 M1；否则只做原型与技术验证，不写业务代码。

### M1 · P0 闭环与试点（第 4–7 月）

范围：学生端下单支付、商家接单出餐、骑手配送、后台审核、支付分账、T+1 结算、退款、日对账。

| 交付 | DoD |
|---|---|
| 四端 P0 功能 | 验收用例 AC-01–AC-15 通过 |
| 支付分账 | 沙箱 + 生产小额验证；分账准确率 100% |
| 对账 | 连续 7 天日对账零差异 |
| 试点 | 1 个宿舍区 + 1 个食堂，日单 300–500 |
| 性能 | 峰值 1000 单/日压测通过，P99 < 500ms |
| 安全 | 渗透测试无高危；等保备案受理 |

**Gate：** 试点 8 周，若日单 < 200 或准时率 < 80%，暂停扩张，先修体验。

### M2 · P1 完整体验（第 8–10 月）

范围：预约自提与产能、集配点/自提柜、拼单、优惠券/满减、会员、评价/投诉、骑手排班、消息通知、商家 PC 后台、BI 看板。

| 交付 | DoD |
|---|---|
| P1 功能 | 全部验收用例通过 |
| 集配渗透率 | ≥35% |
| 日单 | 1500 |
| 商家 | 80 |
| 骑手 | 50 |
| 准时率 | ≥88% |
| 会员付费率 | ≥5% |

### M3 · P2 差异化（第 11–13 月）

范围：团购、跑腿、校园卡（若接口开放）、课表导入、假期专区、多校区、广告位、开放 API（可选）。

| 交付 | DoD |
|---|---|
| P2 功能 | 按优先级交付，未完成项进入 M4 |
| 日单 | 2500 |
| 商家 | 120 |
| 骑手 | 80 |
| 7 日复购 | ≥40% |
| 收入结构 | 非佣金收入 ≥20% |

### M4 · 稳定运营与复制准备（第 14–15 月）

范围：等保三级加固（如需）、密评（如需）、性能优化、成本优化、SaaS 多校区预留、复盘。

| 交付 | DoD |
|---|---|
| 稳定性 | 连续 30 天可用性 ≥99.9% |
| 对账 | 月度零差异 |

## 5. 灰度与上线

| 阶段 | 范围 | 判据 |
|---|---|---|
| 内测 | 员工 + 20 名学生 | 核心链路无阻断 |
| 灰度 1 | 1 栋宿舍 + 1 个档口 | 日单 50，退款率 <5% |
| 灰度 2 | 1 个宿舍区 + 1 个食堂 | 日单 300，准时率 ≥85% |
| 全量 1 期 | 主校区 | 日单 1500，对账零差异 |
| 全量 2 期 | 主校区 + 分校区 | 日单 2500 |

**功能开关：** 拼单、预约、会员、跑腿、团购均独立开关；按校区/楼栋灰度。
**回滚判据：** 支付成功率 <95%、下单成功率 <90%、分账失败 >10 单/日、重大食安/舆情。
**发布窗口：** 避开 11:00–13:00、17:00–19:00；重大变更在周一/周二。

## 6. 验收标准

### 6.1 技术验收

| 项 | 标准 |
|---|---|
| 功能 | P0/P1 用例 100% 通过，P2 ≥90% |
| 性能 | 峰值 8000 单/日压测：下单 P99 < 500ms，查询 P99 < 300ms |
| 可用性 | 连续 30 天 ≥99.9% |
| 支付 | 成功率 ≥99.5%；分账准确率 100% |
| 对账 | 日对账差异 T+3 闭环；月度零差异 |
| 安全 | 无高危漏洞；等保备案完成 |
| 兼容 | 微信小程序 iOS/Android 主流机型；骑手 App Android 8+ |

### 6.2 业务验收

| 指标 | 目标 |
|---|---|
| 日订单 | M2 1500；M3 2500 |

### 6.3 合规验收

- [ ] 运营主体、合同、发票链路可审计；
- [ ] 商户进件与分账授权 100%；
- [ ] 无二清资金池；
- [ ] 网络餐饮平台备案、食安公示、配送食安制度；
- [ ] 等保备案/测评、APP 备案、隐私政策与单独同意；
- [ ] 骑手用工与保险合规。

## 7. 止损与退出

| 条件 | 动作 |
|---|---|
| M1 试点 8 周日单 <200 | 暂停扩张，复盘产品/供给 |
| 连续 3 个月日单 <1000 | 缩减团队，转轻模式 |
| 补贴超预算 20% | 停止现金补贴，转权益 |
| 分账/对账连续 2 月有重大差异 | 暂停新商户，专项整改 |
| 重大食安事故 | 涉事商家下线，全量排查，必要时停业 |
| 校方叫停/政策变化 | 启动退出：商户结算、用户退款、数据移交 |
| 12 个月仍未达盈亏平衡路径 | 评估转「学校购买服务」或终止 |

## 8. 依赖与里程碑风险

| 依赖 | 风险 | 缓解 |
|---|---|---|
| 运营主体设立 | 国资/教育审批 6–12 月 | 提前启动；先用现有后勤公司签约 |
| 微信服务商资质 | 审核周期不确定 | 并行接触持牌聚合/银行存管 |
| 商户进件 | 无照档口卡住 | 自营化/限期办照；先做有照商户 |
| 集配点场地 | 学校不批 | 备选超市合作/自提柜 |
| 等保/备案 | 3–6 月 | 提前立项；先二级 |
| 骑手 App 保活 | 技术不达标 | M0 技术验证；备选第三方 SDK |
| 校外商户准入 | 保卫处不批 | 首期只做校内，校外延后 |
