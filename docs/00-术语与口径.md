# 00 · 术语与口径（宪法级）

> 本文件是全部文档、DDL、接口、埋点的唯一口径来源。任何冲突以本文件为准；修改本文件必须同步下游文档并记录变更。

---

## 1. 金额规范

| 项 | 规定 |
|---|---|
| 存储类型 | `BIGINT`，单位 **分**（1 元 = 100 分） |
| 计算类型 | Java `BigDecimal`，禁止 `double`/`float` |
| 舍入 | `RoundingMode.HALF_UP`，最终结果到分 |
| 展示 | 前端统一格式化为 `¥0.00` |
| 比例 | 用整数基点（bp）存储，`10000 bp = 100%`；佣金 5% = `500 bp` |
| 禁止 | 任何表禁止使用 `DECIMAL(10,2)` 存金额；历史遗留需迁移 |
| 快照 | 订单支付时冻结 `price_snapshot`、`split_rule_snapshot`，历史订单只读快照 |

## 2. 主键与单号

| 项 | 规定 |
|---|---|
| 表主键 | `BIGINT AUTO_INCREMENT`，命名 `id` |
| 业务单号 | 雪花 ID + 业务前缀，`VARCHAR(32)`，唯一索引 |
| 订单号 | `O` + yyyyMMdd + 雪花后 12 位，如 `O202611080000123456` |
| 支付单号 | `P` + 同上 |
| 退款单号 | `R` + 同上 |
| 分账单号 | `S` + 同上 |
| 结算单号 | `ST` + 同上 |
| 幂等键 | 客户端 `submitToken` / 请求头 `X-Request-Id` / 业务唯一索引 |
| 雪花 workerId | 通过 Redis 或配置中心分配，范围 0–1023，禁止硬编码 |

## 3. 订单状态字典（唯一）

| code | 名称 | 说明 | 可迁移到 |
|---|---|---|---|
| 10 | 待支付 | 下单成功，等待支付 | 20, 91 |
| 20 | 待接单 | 已支付，等待商家接单 | 30, 60, 90 |
| 30 | 制作中 | 商家已接单 | 35, 60, 90 |
| 35 | 待取餐 | 商家出餐完成，等待骑手/用户 | 40, 50, 90 |
| 40 | 配送中 | 骑手已取餐 | 45, 60 |
| 45 | 已送达 | 骑手送达，进入售后期 | 50, 60 |
| 50 | 已完成 | 售后结束/确认收货 | — |
| 60 | 售后中 | 退款/投诉处理中 | 50, 90 |
| 90 | 已取消 | 用户/商家/平台取消 | — |
| 91 | 已关闭 | 超时未支付 | — |

**规则：**
- 状态推进一律 CAS：`UPDATE o_order SET status=? WHERE id=? AND status=?`；
- 每次变更写 `o_order_status_log`，禁止覆盖历史；
- 取消/退款必须校验当前状态，禁止跨状态跳转；
- 前端展示以 code 映射，不直接存中文。

## 5. 支付/退款/分账状态

| 对象 | 状态 |
|---|---|
| 支付单 | `INIT → PAYING → PAID → REFUNDING → REFUNDED / PART_REFUNDED`；`INIT/PAYING → CLOSED` |
| 退款单 | `INIT → PROCESSING → SUCCESS / PART_SUCCESS / FAILED` |
| 分账单 | `PENDING → SPLITTING → SUCCESS / PART_SUCCESS / FAILED`；`SUCCESS/PART_SUCCESS → REVERSING → REVERSED / PART_REVERSED` |
| 结算凭证 | `GENERATED → CONFIRMED`（微信自动结算，平台仅确认凭证） |
| 欠款 | `OPEN → PART_RECOVERED → RECOVERED / WRITTEN_OFF` |

## 6. 规模基线（容量与成本统一按此）

| 指标 | 值 |
|---|---|
| 在校学生 | 30,000（主校区 + 1 个分校区） |
| 可服务商家 | 120–180（食堂档口 60–80、校内商铺 20、校外 60–80） |
| 客单价 | 18 元（商品 16 + 配送费 2 的典型组合） |
| 稳态日单 | 2,500 |
| 峰值日单 | 6,000 |
| 设计容量 | 8,000 单/日 |
| 峰值 QPS | 下单 < 10，查询 < 300 |
| 骑手 | 60–120（学生兼职为主） |
| 单均配送时长 | 18 分钟 |
| 定位上报 | 骑手端 10 秒/次；Redis GEO 为主，DB 抽稀 60 秒 |
| 数据保留 | 订单/资金 10 年；轨迹 90 天；日志 180 天 |

> 任何容量、成本、财务测算必须引用本表；引用其他数字需注明来源与日期。

## 7. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 表 | 前缀 + 小写下划线 | `o_order`, `fund_split_order` |
| 字段 | 小写下划线 | `created_at`, `merchant_id` |
| 枚举 | 整数 code + 字典表 | `status=20` |
| 接口 | `/api/{域}/{资源}`，复数 | `/api/orders`, `/api/merchants` |
| 模块 | `ms-{域}` | `ms-order`, `ms-fund` |
| 前端页面 | kebab-case | `order-detail` |
| 事件 | `{域}.{实体}.{动作}` | `order.created`, `fund.split.succeeded` |

**表前缀：**

| 前缀 | 域 |
|---|---|
| `u_` | 用户与学生认证 |
| `c_` | 校区/楼栋/配送点/校历 |
| `m_` | 商家/门店/档口/资质 |
| `p_` | 商品/规格/库存/购物车 |
| `o_` | 订单/售后 |
| `fund_` | 支付/退款/分账/结算/对账 |
| `d_` | 骑手/配送 |
| `mk_` | 营销/会员/拼单/团购/广告 |
| `rv_` | 评价/投诉 |
| `e_` | 跑腿 |
| `sys_` | 系统/配置/日志/outbox |

## 8. 模块归属（裁决结果）

| 能力 | 归属模块 | 说明 |
|---|---|---|
| 购物车 | `ms-order` | 购物车是下单前置，不放商品域；表名 `o_cart` |
| 库存 | `ms-product` | 表 `p_stock` / `p_stock_log` |
| 支付/分账/结算 | `ms-fund` | 独立模块，独立表前缀，独立权限 |
| 配送 | `ms-delivery` | 含骑手、排班、轨迹、配送单 |
| 营销/会员/拼单/团购 | `ms-marketing` | 表 `mk_`，拼单/团购独立子域 |
| 跑腿 | `ms-errand` | 表 `e_`，复用配送运力 |
| 评价/投诉 | `ms-review` | 表 `rv_` |
| 管理后台 | `admin-api` + `apps/admin` | Web 端，独立构建 |
